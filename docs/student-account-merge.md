# 중복 학생 계정 통합

## 목적

반마다 별도 학생 계정을 만들던 운영 방식에서 생긴 중복 계정을 하나의 개인 계정으로
합친다. 학원 관리자가 대표 계정을 명시적으로 선택하고, 중복 계정의 반 소속과 학습
이력을 대표 계정으로 이동한 뒤 중복 학생 ID를 삭제한다.

이 도구는 카카오 로그인 적용 전 기존 데이터를 정리하기 위한 운영 기능이다. 자동 후보
탐지는 참고 정보일 뿐이며 자동 통합하지 않는다.

## 권한과 후보 기준

- 학원 관리자만 후보 조회, 영향 미리보기, 통합 실행을 할 수 있다.
- 현재 활성 학원 안의 학생끼리만 통합할 수 있다.
- 이름만 같으면 후보로 표시하지 않는다.
- 정규화한 이름이 같고 아래 중 하나 이상을 만족하면 같은 후보 묶음으로 표시한다.
  - 학생 전화번호 일치
  - 보호자 전화번호 일치
  - 학교와 학년 모두 일치
- 전화번호는 관리자 화면에서도 뒤 4자리만 표시한다.
- 후보 탐지에서 빠진 계정을 서버가 임의로 합치지 않는다.

## 관리자 동선

1. 학생 관리에서 **중복 계정 정리**를 연다.
2. 후보 묶음의 일치 근거와 학생 ID, 상태, 반 이력, 마스킹된 연락처를 확인한다.
3. 유지할 대표 계정 하나와 삭제할 중복 계정을 선택한다.
4. **영향 확인**에서 이동 건수와 충돌 여부를 확인한다.
5. 충돌이 없으면 `대표 ID {id}` 확인 문구를 입력하고 실행한다.
6. 실행 후 학생 목록과 후보 목록을 다시 확인한다.

대표 계정의 이름, 학교, 학년, 보호자·학생 연락처, PIN, 동의 상태, 점수 공개 설정은
그대로 유지한다. 중복 계정의 프로필 값을 자동으로 덮어쓰지 않는다. 따라서 대표 계정은
로그인과 개인정보 상태까지 확인한 뒤 선택해야 한다.

## 이동 및 폐기 범위

대표 계정으로 이동하는 데이터:

- 반 소속과 종료 이력
- 출결 및 수업 피드백
- 숙제 기록
- 시험 제출과 연결된 답안 상세
- 영상 진도
- 클리닉 신청과 숙제 진행
- 개인정보 동의 이력
- 푸시 기기와 알림
- 학생 UI 의견

중복 계정의 자동 로그인 토큰은 보안상 대표 계정으로 이전하지 않고 삭제한다. 이미 열린
중복 계정 세션도 이후 요청에서 더 이상 유효한 학생을 찾지 못하므로 다시 로그인해야 한다.

## 충돌 처리

다음 자연키가 대표 계정과 중복 계정 사이에 겹치면 통합을 실행하지 않는다.

- 같은 반 소속
- 같은 수업, 숙제, 시험, 영상
- 같은 클리닉 신청
- 같은 클리닉·숙제 진행 조합
- 같은 알림 원본 키

충돌 데이터를 임의 선택하거나 덮어쓰면 출결·점수·진도 손실이 생길 수 있으므로, 현재
단계에서는 관리자가 원본 기록을 비교해 먼저 정리해야 한다. 미리보기와 실행은 같은 충돌
검사를 하며, 실행 시 선택한 모든 학생 행을 잠근 뒤 하나의 트랜잭션으로 처리한다.

## 감사 이력과 배포

`student_account_merges`에는 개인정보 사본 없이 아래 값만 보관한다.

- 학원 ID
- 삭제된 원본 학생 ID
- 유지된 대표 학생 ID
- 실행 관리자 ID
- 실행 시각

배포 순서:

1. 운영 DB 전체 백업
2. `migrations/2026-09-20-01-add-student-account-merges.sql` 실행
3. 테이블과 인덱스 생성 확인
4. 애플리케이션 배포
5. 후보 한 묶음으로 미리보기 후 소량 통합
6. 학생 로그인, 반 전환, 과거 학습 기록 조회 확인

운영은 `ddl-auto: validate`이므로 테이블 생성 전에 코드를 배포하면 애플리케이션 시작이
실패한다. 실제 통합 후에는 롤백 SQL로 원본 데이터를 되살릴 수 없으므로 DB 백업을
복구 수단으로 사용한다.

## 카카오 로그인 통합 시 확인할 점

현재 `main`에는 카카오 계정 연결 테이블이 없다. 카카오 인증 브랜치를 다시 올릴 때는
학생을 직접 참조하는 카카오 계정·보호자 연결 테이블을 이 서비스의 명시적 참조 목록에
추가해야 한다. 추가하지 않으면 외래 키가 통합을 막거나 계정 연결이 원본 ID에 남을 수
있다.
